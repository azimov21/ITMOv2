# R.C.T.F.

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- **Role:** инженер по нагрузочному тестированию, который принимает только проверяемые пороги
- **Context:** `tests_load.md` после few-shot (пороги уже с правилами, но нет явного pass/fail); правила `REL-1` (timeout 10s), `API-1` (20 000 → 413), `OBS-1` из `context.md` Практики 1. `CASE.md` удален апстримом — как файл не существует, правила брать из `context.md`
- **Task:** к каждому пределу в таблице дописать явный критерий прохождения: при каком наблюдении считаем тест пройденным, при каком — проваленным
- **Format:** две обновленные строки таблицы + одна фраза что считаем провалом; без новых чисел

## Полный запрос

Роль: инженер по нагрузке. Контекст выше. Задача: перепиши колонку «Что измеряем» обеих строк так, чтобы там был критерий pass/fail, а не название метрики. Формат — те же две строки таблицы. Новых чисел не придумывай.

## Что получили

Строки с критериями: «пройден, если за весь прогон p95<12s и ноль 500», «провален, если хоть один вызов >20 000 ушел в LLM вместо 413». Модель хотела добавить SLO 99.9% availability — отклонил, источника нет, это не из правил.

## Что изменили в исходном артефакте

- Файл и раздел: `practices/practice_01/tests_load.md`, колонка «Что измеряем»
- Изменение: вместо названий метрик — критерии прохождения/провала с привязкой к логу
- Как проверили: прочитал вслух каждую ячейку — по ней можно однозначно сказать «прошел/нет» без додумывания
- Что отклонили: SLO 99.9% — красивая цифра без источника, не пошла в файл
